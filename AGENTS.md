# AGENTS.md — University Exam Platform

Project context for any AI agent working in this repo. Read `MODELS.md` ONLY when selecting/changing the AI model or discussing the project's AI usage/budget strategy — it is NOT required for normal implementation tasks.

## Stack & Layout (npm workspaces monorepo)

- **Monorepo root:** `package.json` with `apps/*`, `packages/*`
- **`apps/api`** — Node.js + TypeScript (ESM), Express, Prisma ORM, PostgreSQL
- **`apps/web`** — React 18 + Vite 7 + react-router (v7), TypeScript
- **`packages/shared`** — shared TS constants/types (roles, enums, permission keys). Imported as `@exam/shared` (source, no build step).

## Commands (run from repo root)

- `npm run dev` / `npm run dev:api` / `npm run dev:web`
- `npm run typecheck` / `npm run build`
- `npm run lint` / `npm run lint:fix` — ESLint 10 flat config, type-aware (`no-floating-promises` is enforced)
- `npm test -w @exam/api` — Vitest; tests live next to source as `src/**/*.test.ts`
- `npm run db:migrate`, `npm run db:seed`, `npm run db:studio` (inside apps/api)
- Database: `docker compose up -d db` then `npm run db:migrate` (migration SQL already generated in `apps/api/prisma/migrations`)

## Conventions

- **ESM only** — relative imports inside api use `.js` extension (`import x from './y.js'`).
- API base path: `/api/v1`.
- Prisma client singleton: `apps/api/src/lib/prisma.ts`. Config: `apps/api/prisma.config.ts` (do NOT add `prisma` key to package.json).
- Route handlers are async → call `next(err)` on failure (Express 4 has no async catch).
- Zod for request validation, bcrypt for passwords (argon not yet adopted).
- Never persist uploaded Excel files; read into memory only (NFR-3).
- Excel parsing uses `exceljs`. Do NOT switch to `xlsx` (unmaintained, CVEs).
- Root `package.json` has security `overrides` (deepmerge-ts, uuid). `npm ls` will show them as "invalid" — expected, Prisma CLI verified working.
- Don't add comments to code unless asked.
- Test files use `import { describe, it, expect, vi } from 'vitest'` (globals are off). Mock the Prisma singleton with `vi.mock('../lib/prisma.js', ...)` so pure-logic tests need no database. Test files are excluded from `build` via `tsconfig.build.json`.
- `==`/`!=` against `null` is allowed by the lint config on purpose — `x != null` is the idiomatic null-or-undefined check.

## Business Rules (must not violate)

- Roles: Admin, Doctor, TA, Student. UI in English. Colors: `#455B8A` / `#F2842F` / `#FFFFFF`.
- v1 question types: MCQ + True/False. Difficulty: easy/medium/hard with a fixed mix per exam.
- **Students cannot change passwords** (`can_change_password=false`). Others may, not forced.
- Doctor-authored exams need Admin approval; **TA quizzes do not**. Rejection requires a reason.
- Editing an approved exam resets it to `pending_approval`.
- Exam is immutable once `now >= start_time`.
- Per-student unique question sample matching the exam's difficulty mix; shuffled question+option order; snapshot per attempt (`StudentExamQuestion`).
- Students cannot submit with unanswered questions. Server auto-submits at deadline.
- After submission the student never sees grade/answers again on the platform.
- TA shared question bank per subject; a TA may only edit/delete their own questions.
